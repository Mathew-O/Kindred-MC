# F-05c — Read-only candidate proposal, admitted inventory moves and mutation authority recheck
Date: 2026-10-17 EDT; report 2026-10-17.
Antigravity / uncommitted main, no commits. Complete for this child slice; parent F-05 remains open.

Read-only candidate proposal, admitted inventory moves (`native_swap`), and mutation-time authority rechecking eliminate speculative inventory mutation and unauthorized workstation manipulation:
1. **Read-Only Candidate Generation in `PlayerRuntime.evaluateNativeCandidates`:**
   - Eliminated speculative calls to `player.getInventory().setStack(...)` across all candidate generators: food selection, tool equipping, crafting table retrieval, and furnace retrieval.
   - Candidate generation now returns a proposed `native_swap` operation (`sourceSlot`, `targetSlot`) bundled into candidate parameters when an item must be brought to the hotbar.
   - Unselected and rejected candidates perform zero item movements or inventory mutations.
2. **Durable Admitted Inventory Swaps (`NativeSwapAction`):**
   - Registered `native_swap` skill descriptor with `Intent.SWAP` and 5-second prepaid execution slice.
   - Dispatches via `ActionAdmission` (`native_swap`) through `PREPARED -> DISPATCHED -> VERIFIED` on the durable SQLite ledger.
   - Performs authentic inventory swap between slots via `NativePlayerBody.swapSlots(lease, sourceSlot, targetSlot)`.
   - Strict 100% item component and count conservation check (`verifySwapConservation`) scans all 36 player inventory slots before and after swap, asserting exact matching of all items and counts across the whole inventory.
3. **Mutation-Time Authority and Claim Recheck (`NativeSmeltAction`):**
   - In `NativeSmeltAction`, records `setupRevision` at plan time.
   - At mutation time (`tick()` and `permits()`), rechecks:
     - Target chunk loaded and furnace block entity instance valid.
     - Reach <= 4.5 blocks.
     - Work setup revision matches original plan-time revision (`runtime.nativeSetupStatus().revision() == plannedSetupRevision`).
     - Server edit policy (`EditPolicy.evaluate(PLACE, "minecraft:furnace")`).
     - Claim validity on the furnace block position.
   - If policy is revoked, claim is contested, or setup area revision changes asynchronously during admission, mutation is refused and the action fails cleanly without mutating furnace inventory.
