## Scope and implementation

**Test-only.** Nothing in the game changes.

**Found:** #357's CI, run 43722834395 attempt 2 (job 132859627895), ended in a crash of the game-test server, not a test
failure: `NullPointerException: Cannot invoke "ServerPlayerEntity.getInventory()" because the return value of
"NativePaidSkillsGameTests$Fixture.player()" is null`, at `NativeOwnRanchGameTests.java:471`, in
`withOneCarrotItGrowsMoreThenKeepsAPairOfPigs`. The pig test's last step, retried until it holds, read its player's
inventory for a log line and two messages; its player's body was gone. A retried step's assertion fails only its own test,
but any other exception leaves the step and the server crashes, taking every test after it.

**The change:**
- `NativeOwnRanchGameTests`: the pig ranch's last check is a method, `pigsPenned`, called with the pen; each carrot count
  in a message, log line or check reads through the class's own null-safe `held` (-1 with no body); each "Standing" step
  asks for a body first.
- `NativeCompoundGameTests`: the same "Standing" guard, and an assertion that its body is in the world before each of the
  three retried steps that read its inventory.
- New test, `withItsPlayerGoneTheRanchCheckFailsAsAnAssertionNotACrash` (batch `ownRanchNoBody`): a player established,
  the fixture's handle on it then pointed at no body, and `pigsPenned` called with a pig pen and no pigs. It passes only
  if the check fails as an assertion ("The pair penned …"), and catches anything else the check throws, so it cannot
  itself crash the server.
- No timeout, bound, required number or check changed.
