## Scope and implementation

**Test-only.** Nothing in the game changes.

**Found:** on #380's CI (run 43783885635, job 133027070300),
`NativeBringGameTests.aFrontRailsDropBornInsideTheBoatsBoxIsStillPickedUp` failed "Hal still in play". The bring had
ended "Brought home" at 02:07:31. Its last check was then retried for a minute, each time not yet so: "Rails (but the
cell floor's), the cart and dirt all taken back, …: 63 rails, 1 carts, 0 lecterns, **3 dirt** …". The server log
shows this 119 times. Then, as the test ran out, Hal's runtime stopped ("Kindred memory files written at the stop",
02:08:32) and `f.player()` was null. The check's first assertion, "Hal still in play", was the failure the test
reported. The minute's reason, a dirt short (F-22c84's cause #3), was in the log only.

**The change, in `NativeBringGameTests`:**
- The last check needs Hal in play through a small helper, `inPlay(context, hal, lastNotYet)`.
- The retried step's catch keeps the failure's message while Hal is in play (`lastNotYet`), never the out-of-play
  message itself.
- Out of play with a reason kept, the failure says "Hal out of play as the test ended; before that, not yet: " and
  the reason. With none kept, it says "Hal still in play", as before.
- New test, `outOfPlayAsTheTestEndsTheBringCheckStillSaysWhatWasNotYetSo` (batch `bringOutOfPlay`): the helper given
  no player and #380's reason. It passes only if the failure names that reason, and it catches anything else the
  helper throws, so it cannot crash the server.
- No timeout, bound, required count or check changed.
