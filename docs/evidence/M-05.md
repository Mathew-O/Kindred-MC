## Scope and implementation

User-visible behavior: an operator puts vanilla structure files (`.nbt`) and Sponge schematics (`.schem`) in `config/kindred/schematics`, each with an optional `<name>.license` (`creator=`, `license=`, `source=`). `/aiplayer build <name> <x y z> [turns] [player]` then has a native player build one from its own blocks, turned as asked (E-08b). The start message credits the creator, the license and the source, or says `no license recorded`. `/aiplayer build list` lists what there is. Nothing is fetched from anywhere (D8).

- **`Nbt`** (core, new): Minecraft's binary NBT, read gzipped or not. It is bounded against a hostile file: 16 MB unpacked, 64 deep, and no list or array longer than what is left to read.
- **`Schematics`** (core, new) reads both formats into blueprints:
  - **Structure files**: one palette or the first of several, blocks by position and state, the file's author when it has one.
  - **Sponge schematics, versions 2 and 3**: the palette by name, blocks as varints with x fastest, then z, then y, and the metadata's name and author.
  - What it keeps and leaves out:
    - air is space to keep clear; structure void is neither a block nor space;
    - block entities are placed empty, their contents never copied (a schematic's chest of diamonds is a chest);
    - entities are left out;
    - blocks a survival player cannot get as an item are left out and listed (`UNOBTAINABLE`): bedrock, spawners, end portal frames, command blocks, infested stone, farmland and the like.
  - Sizes are bounded by the blueprint's (96 a side, 32,768 blocks).
- **`SchematicLibrary`** (adapter, new) handles the folder and the game side:
  - It reads files off the game thread (8 MB at most), with the license file beside each.
  - It checks every block state against the game's own block parser, leaving out and noting any this version does not know.
  - It notes a file saved by a newer Minecraft.
- **Props** (core and adapter, `ConstructionPlanner.Kind.SUPPORT`). Schematics bring blocks a hut never has, such as logs lying in rows with nothing at their ends. A lying log is placed only against a face along its axis, so the first of a row has nothing to be set against. The planner then props it, as a player does: a short column of scaffolding from the ground up to the cell beside it, only where the block can then be placed. The runner records each prop from its finished task, and the prop comes down with the rest of the scaffolding.

Found on the way:
- **Unrecorded props.** The runner first kept the prop it was placing in one field. Re-planning could run between the block landing and the task's finish, so a prop could go unrecorded and be left standing. Props are now recorded from the finished task itself.
- **Masked failures.** The fixtures' checks retry each tick, and once a test ran out and its runtime stopped, the message only said the player was gone. They now keep their first failure.

Changed modules/files: `Nbt`, `Schematics` (core, new), `ConstructionPlanner` (`SUPPORT`, `prop`), `Generators` (`NAMES`); `SchematicsTest`, `PropTest`, `BuildSimulation` (new; the whole-build simulation, shared), `GeneratorsTest`; `SchematicLibrary` (new), `BuildRunner` (props), `PlayerRuntime` (`startSchematicBuild`, `listBlueprints`, the start message's credit, `nativeStatusLine`), `PlayerCommands` (`build <schematic>`, `build list`); `NativeBuildGameTests` (`aStructureSavedByVanillaIsReadAndBuiltTurnedAQuarter`).
Dependencies satisfied: E-08a; E-08b in progress.
Schema/configuration changes and migration coverage: none. The new folder is `config/kindred/schematics`.

Runs of the build class alone, once props were in:
- 20 of 24 passed in all.
- Two failures were the unrecorded prop, behind the masked message; both are fixed.
- In two runs the build never began. The player stayed idle after the build had started, both times as the kiosk's runtime started while the hut test's runtime was stopping in the same server. The cause is not yet known.
- After the last fixes, 18 of 19 passed, the one failure being that stall.
- The stall came once more in a suite on 2026-10-22 (E-07e's suite 5), with the status line logged. Every gate was open, but the routine refresh had never run: the player's tick hook was not running. The line now also reports the body's ticks, its age, and whether it is listed and connected, to tell next time whether the player is not ticking or a stale body's hook is.
- It came again in E-07e's gold suite (276/277). The body had ticked twice (`bodyTicks=2 age=2`) and was then no longer ticked by its world, though it was listed, connected and not removed. A world ticks an entity only in a chunk it simulates, and the game-test server simulates almost nothing beyond the player's own chunk (E-07e found a piglin frozen one chunk away). The line now also reports the body's world, whether that world lists it and finds it by its id, and whether its chunk is simulated or force-loaded.
- **Found and fixed** on 2026-10-22, in F-10h's suite (278/279). The line showed `simulated=false forced=false`: the body was in its world and found by its id, but its chunk was not simulated. The kiosk fixture repositions the player before the build, and sometimes that is across a chunk border, depending on where the test lands. A native body's chunk tickets moved only in its own tick. Moved outside it into a chunk nothing else kept simulated, it was never ticked again to move them, and froze there. A human's client re-centres its tickets with its next movement packet. A native body now re-centres them whenever it is set down in another chunk section. On a live server a `/tp` of a native player far away would have frozen it the same way.
  - `aBodyMovedOutsideItsOwnTickIsStillTickedWhereItLands` (new) moves a body 4,096 blocks by a fixture repositioning, as a `/tp` would. It passes; its control, run by hand without the fix, froze with the stall's exact line (`bodyTicks=2 age=2 … simulated=false forced=false`, no tick after the move).

## Remaining limitations and handoff

- Litematica files are not read.
- Older saves are not upgraded through vanilla's data fixer: a block renamed since is left out and noted.
- Only the first of a structure's several palettes is used.
- Builds larger than the kiosk and hut have not been played in the world.
- Blocks with no placement rule yet are skipped (E-08a).
- The rare start that never began is fixed (a body moved into an unsimulated chunk froze there); the kiosk fixture has not failed since in the runs recorded in [validation](../validation.md).
