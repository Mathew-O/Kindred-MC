## Scope and implementation

Found in the Factions runs (factions2b, seeds 109 and 110, goal none). Each player logged about 1,000
`native_goto BLOCKED: No walkable route toward …`, the planner giving up at its node limit. The same target was tried
40 to 60 times: seed 109 Kindred toward 52 83 -60 45 times, seed 110 Echo toward 45 65 -50 59 times. The lines carried
no task label, so the routine that issued them could not be read from the log.

**The trace (2026-11-09).** Every ended task's outcome line now says where it came from. That is its campaign or build
step's label, or its life task's; or else `from <method>:<line>`, the routine that proposed it.
`NativeTaskCandidate` records its proposer when it is made (a `StackWalker` frame, no call sites changed). The
autonomous choice hands it to the dispatch, and a task asked for by a command carries none. The same label goes to the
run observer (`RunObserver.ended`), so an unattended run's record has it too. Behaviour is unchanged.

Changed: `PlayerRuntime` (`NativeTaskCandidate.source`, `dispatchSource`, `outcomeLabel`); test
`NativeOwnRanchGameTests.withItsCabinStandingItKeepsAPairOfCowsItHasSeen` (an observer: every ended task labelled).
