# F-34d — A message's identity on the Wire is its sender's

Status: complete

## Scope and implementation

**The report.** In RUNNER 2's keyed F-34c run (seed 101, Factions), Echo joined at tick 1983 and the World Record has
no Wire message for it, while it has one for Sol's join. The console shows Sol joined at 19:14:29 and was told, and
Echo joined at 19:14:56, 27 s later.

**The cause, by code reference:**
1. `PlayerRuntime.factionAct`, JOIN: the join's events go into `drafts` through `FactionsService.request(..., held)`.
   Then `recordAndTell(drafts, ids -> factionMessage(entry, id, "faction.joined", "", line, ids))` runs. The message's
   one fact is `what` = the reply's line, `"Joined " + faction.name()` (`Factions.join`). So Sol's and Echo's messages
   were the same kind, on the same faction channel, with the same fact.
2. `Wire.send`: the dedupe key is `budgetKey + "|" + message.sameness()`. A faction scope's `budgetKey` is the
   faction's alone (only an earshot scope adds the sender), and `Message.sameness()` was the kind and the facts. So
   Echo's message 27 s after Sol's was refused with `DUPLICATE` (the faction channel's window is 60 s).
3. `KindredWire.send`: a refused message is logged at debug and returns. The Record's note of a message
   (`WebFeed.MESSAGE`) is written only for a sent one with receivers. So nothing of Echo's join reached the Record's
   messages, though the join event itself was written.

That is a bug: two players telling the same thing are two pieces of news, not one said twice.

**The change.** `Wire.send`'s channel dedupe key includes the sender (the companion id, or `server` for the server's
own notices). One sender's same message within the window is still refused, as before. The budgets per channel and
per person are unchanged, so this cannot raise the volume past them. A person still hears the same words once in a
while whoever says them (`heardSame`, keyed by the receiver and the words): `WireTest`'s public-notice case requires
it (two players telling the same shortage, each person in earshot hears it once), and it is kept. So a person in the
faction hears "Joined Oak" once, but every AI member is told each join, and each is in the Record.

Not body behaviour: the Wire's dedupe only.

Changed modules/files:
- companion-core: `wire/Wire` (the dedupe key), `WireTest` (one case).
- gametest: `NativeFactionTellGameTests` (one fixture).
- docs: this file, the tracker.

## Remaining limitations and handoff

- A person hears identical words from two senders once in a while (the kept `heardSame` rule). Whether a person should
  hear each player's own news, such as each join, is a wording question for the voice, not this fix.
- A refused message is logged only at debug (`KindredWire.send`), which is why the run's console said nothing. The
  counts are in `KindredWire.counts()`. Raising that log's level is left as it is, since budget refusals are routine.
