# E-20d — The voice and the strategist as separate switches, with separate budgets

Date: 2026-11-14
Agent / branch: Claude, Session B (claude/voice-alone-1114)
Build: the branch's head (see the PR); base main `fbc5f0f`
Status: complete

## Scope and implementation

**The bug.** RUNNER 2 ran a keyed F-34c run on seed 101, Factions, with `strategist=off; voice=on`. The strategist
consulted anyway: `Kindred strategist: PRESS_ON (6852 in, 0 cached, 108 out tokens, 1931 ms)`, for each of three
players, every 20 to 40 s. That is about 0.8M input tokens in 20 minutes. The calls were off the tick, so the rule
against a model call on a tick held, but nobody had asked for them.

**The coupling, by code reference:**
1. `tools/eval/run.py`, `environment()`: `wants_model` is true for `strategist=on` **or** `voice=on`. That passes every
   `KINDRED_STRATEGIST*` setting, `KINDRED_STRATEGIST=on` included, and the provider's key. The voice needs the key,
   since it speaks through the strategist's connection.
2. `StrategistBridge.fromEnvironment`: with `KINDRED_STRATEGIST=on` and a key, the bridge exists, and its `advice` and
   `rescue` are on by default.
3. `EvalBootstrap`, case 0: `runtime.rescue(scenario.rescue())` and `runtime.advice(scenario.advice())`. The scenario's
   own `strategist` flag gated nothing. So `strategist=off` with `voice=on` meant the stance was asked, and rescues
   were too. Questions (`StrategistBridge.ask`) were gated by nothing, though `advice`'s own doc says advice off means
   "asked only for rescues".
4. One daily budget: `admit` and the token counters were shared by advice, questions, rescues, the voice and the
   Chronicle's pages. The voice could spend the stance's budget, and the stance the voice's.

**The change:**
- **`EvalScenario.askAdvice()` and `askRescue()`** (core) are true only with `strategist=on`, and with `advice` and
  `rescue` on respectively. `EvalBootstrap` applies them, and logs `advice …, rescue … (strategist …, voice …)`. With
  `strategist=off; voice=on`, the voice gets its lines and the key, and nothing else is asked of a model.
- **`StrategistBridge.ask`** is gated by `advice`, as its doc says.
- **`KINDRED_ADVICE=off`** (`KindredMod`): the same choice on an operator's server, beside the existing
  `KINDRED_RESCUE=off`. No stance and no questions; the voice and the pages, if used, still run.
- **Budgets per use** (`StrategistBridge.Use`): ADVICE (the stance, questions, rescue plans), VOICE (talk and Wire
  lines) and PAGES (the Chronicle).
  - Each use has its own daily budget a player and in all, checked and charged on its own (`admit`, `charge`).
  - Advice keeps `KINDRED_STRATEGIST_PLAYER_DAILY_TOKENS` and `KINDRED_STRATEGIST_DAILY_TOKENS`. The voice and the
    pages get `KINDRED_VOICE_*` and `KINDRED_CHRONICLE_*`, the same sizes unless set.
  - One use spent leaves the others untouched. The per-minute rates (six a player, twelve in all) stay shared, as a
    guard on the provider.
  - The start line names all three budgets, and a spent one says which.
- **`tools/eval/run.py`'s docstring** says what `voice=on` with `strategist=off` now means.

Not body behaviour: model use and configuration only. A run with no key behaves exactly as before: there is no
bridge, so rescues and advice never asked anything. The default scenario line, `strategist=off; voice=off; …;
rescue=on`, is that case.

Changed modules/files:
- companion-core: `eval/EvalScenario` (`askAdvice`, `askRescue`), `EvalScenarioTest` (one case).
- companion-server-adapter: `EvalBootstrap`, `KindredMod` (`KINDRED_ADVICE`), `StrategistBridge` (`Use`, the per-use
  budgets, `ask` gated by advice, `usedToday`, `budgetsForTest`), `PlayerRuntime` (`strategistForTest`).
- gametest: `NativeVoiceGameTests` (two fixtures).
- tools: `eval/run.py` (docstring).
- docs: this file, `operator-guide.md` (the settings and a paragraph), the tracker.

## The "0 cached" on every call: F-19f, filed

RUNNER 2's lines show `0 cached` on every consultation. The stance prompt's stable prefix is `StrategistPrompt.SYSTEM`,
the instructions and the guide: 10,875 characters, about 2,000 words, roughly 2.5k to 2.8k tokens. The Claude path
already marks it `cache_control` (ephemeral, `ClaudeStrategist`). The current Claude models' minimum cacheable prefix
is 512 tokens, so on Claude it should cache, and a read of 0 across calls 20 to 40 s apart points elsewhere:
- a prefix that changes between calls;
- a provider that is not Claude (the OpenAI-compatible path reports `prompt_tokens_details.cached_tokens`, which a
  provider may not fill);
- the requests not reaching Anthropic's cache.

The run's own start line, `Kindred strategist on: <provider> model …`, decides which. It is not in hand, so this is
filed as F-19f, not fixed here.
