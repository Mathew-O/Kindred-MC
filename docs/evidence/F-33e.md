# F-33e — The Chronicle's read-back past 10,000 pages

Date: 2026-11-16
Agent / branch: Claude, Session B (claude/chronicle-readback-1116)
Build: the branch's head (see the PR)
Status: complete (the Chronicle's storage path; no body behaviour)

## The finding

Found while checking the comms lanes for the Factions month run (the lead, 2026-11-16).

At every start, `ChronicleKeeper.start` read its pages back from the World Record with
`host.events(Set.of(Chronicle.PAGE), 0, BATCH)`. `BATCH` is 10,000, so it read only the first 10,000 page events, the
oldest. Past that point, a restart:
- set `through` from those old pages, not from the last page written;
- kept old pages as each player's newest seven, and old weeks and months as the world's and factions';
- re-read every event after the old `through` at the next day. That wrote pages again for days already written into
  the append-only Record, spent page calls on them, and left the newest pages out of memory.

When it would bite: RUNNER 2's f34c3-37adcdc run wrote 3 player-day pages a game day with 3 players. That is about 8
a game day at 8 players, so 10,000 pages at about 1,250 game days, around day 17 of the month run's 30 (72 game days a
real day). Weeks and months add a few more.

## The fix

- **`start` reads every page.** It reads in batches of 10,000, in the Record's order, each after the last id read,
  until a batch comes back short (`readBack`). Each batch is folded in as it comes, as before (`keep`, `keepAbove`, the
  highest `through`), so only each scope's newest seven pages and the highest `through` are held, never every page.
- **A failed read blocks.** If a batch cannot be read, the Chronicle writes no pages until the next start, and says
  so. Before, a failed read set `through` to 0, so the next day would have read and paged the whole Record again.
- **Off the server thread.** Each batch is read on the Record's ordered writer, as the start path read before. Only
  folding a batch into the few pages kept runs on the server thread, and the start line gives that share.
- **The start line** says how many pages the Record held and how long the read-back took: `Chronicle: N page(s) read
  back of M in the Record, through event T, in X ms (Y ms of it on the server thread)`.
- `ChronicleKeeper.throughForFixtures` (new) gives the fixture the last event read.
