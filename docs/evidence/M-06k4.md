## Scope

The lead's ask, 2026-11-14: a runbook in `operator-guide.md` for the owner's 12 GB server:
- start;
- connect all;
- settle any held actions, with the evidence shown and how to choose;
- resume;
- what to check in the Record after a crash.

Each command was tested against a real server start, as F-31g's soak ran.

Written: `operator-guide.md`, "The month run: a runbook (M-06k4)", before "A month-long run: what grows on disk".

## The walk

Seed 101; Minecraft 1.21.1, Fabric Loader 0.19.5, Fabric API 0.116.17+1.21.1; OpenJDK 21; heap 6 GB;
`maxNativePlayers=8`. Driven by a script on `tools/soak/soak.py`'s `Server` (the console over stdin), each command's
answer kept.

1. **The world.** An evaluation run (8 players, `founders=3`, `mode=factions`, 6,000 ticks), then
   `aiplayer mode world factions` at the console. It answered "This world now plays Factions; AI players play at
   OPTIMAL_SURVIVAL."
2. **A plain start.**
   - `aiplayer native list`: 8 lines, each "ESTABLISHED, offline; stopped. ... explicit connect is required."
   - `aiplayer native connect <name>` for each: "Native body connected; stopped. Resume explicitly.", "<name> joined the
     game" and the atlas recall line.
   - `aiplayer native resume <name>` for each: "Resumed; autonomous progression active (OPTIMAL_SURVIVAL)."
   - `aiplayer mode world`: the Factions rules.
   - Four minutes of play, then SIGKILL.
3. **The start after the kill.**
   - `aiplayer native list`: Bram and Eli "Unresolved action ledger rows detected (1)"; the other six ready.
   - `aiplayer native status Bram` and `... Eli`: the same block.
   - `aiplayer native settle Bram`: "Bram's native_break 72cbb812-... is not plain from the evidence: minecraft:andesite
     at -390, 51, -194: now minecraft:andesite, still there; the saved inventory differs from before the action
     (...). Choose: aiplayer native settle Bram done|notdone", then "Bram: 0 settled; 1 left to settle. It stays
     blocked."
   - `aiplayer native settle Bram notdone`: "Settled Bram's native_break as not done (the console, the operator's
     choice): ...", then "Bram: every action settled (1). Connect it, then resume it."
   - The same for Eli: andesite at -517, 47, -334, still there, `notdone`.
   - `aiplayer native list`: Bram and Eli "Settled; native body is offline; explicit connect is required."
   - Connect and resume for all 8: every one connected and resumed. A player running at the crash answers connect with
     "automatic progression remains disabled" rather than "stopped. Resume explicitly"; resume works the same.
   - `aiplayer mode world`: Factions.
   - `faction list` and `faction power Kindred` from the console: refused ("Only a player makes faction requests; an
     operator uses /faction as <player> ...").
   - `tick query`: "P50: 24.6ms P95: 43.8ms P99: 60.7ms".
   - `stop`: saved, "All dimensions are saved".
4. **The Record, server stopped, on a copy.**
   - The runbook's code block, pasted into bash as written: `ok`, `0`, and the two `action.settled` rows (by the
     console, decided by the operator, with the evidence).
   - `./gradlew :companion-testkit:runRecordAudit --args=<copy>`: `{"audited": 116, ... "violations": []}`.
5. **One more start.**
   - Connect and resume all 8.
   - `faction as Kindred info`: "Kindred_Hold [KIN] 3/10 members, power 30, claims 0 / 30" and its members.
   - `faction as Kindred list`: the three factions.
   - `faction as Kindred power`: "Kindred: power 10 / 10".
   - `faction as Kindred coins`: "Coins: 500.00".
   - `stop`: 2 seconds to "All dimensions are saved".

## Finding

**One stop hung.** The evaluation run's own stop (step 1: `server.stop` at the end of its ticks, not a console `stop`)
logged "Saving worlds" and then spun for 20 minutes in vanilla's chunk saving: the server thread in
`ServerChunkLoadingManager`'s save loop, with no Kindred frame on any busy thread. Kindred had already written its
records and memory at its own stop.
- It was killed; the next start loaded normally.
- Three thread dumps are kept with the walk, not committed.
- The two console stops after it took 2 s. F-31g's soak stopped five times on `3196401` without a hang, its evaluation
  run's stop included.
- Not reproduced; one occurrence. The runbook says: if a stop hangs past "Saving worlds", kill it and treat the next
  start as after a crash. It goes to the lead as a finding of its own.

## Not walked

- Windows: the runbook gives the substitutions, unwalked.
- A settlement decided from the evidence without the operator: it is plain only when the save postdates the action,
  which a crash rarely leaves. It is shown by F-31g1's fixtures.
