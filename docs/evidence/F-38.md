## Scope and implementation

User-visible behavior: none intended on vanilla. Core now asks what a thing is instead of comparing names, so the
later slices can hand it a server's own tags (a mod's tagged log is a log).

Changed modules/files (slice 1, companion-core only):
- `VanillaIds` (new): the one main class in core that names `minecraft:` ids. Groups stand for a tag (exact when
  the list is that tag's vanilla 1.21.1 content, so the server's tag replaces it; not exact when no tag says the
  same, named in the `kindred` namespace); single ids each say the tag, component or attribute they would use;
  vanilla tool tiers.
- `Capabilities` (new): an immutable snapshot of plain strings (group members, tool kind and tier). Vanilla from
  `VanillaIds` until the adapter installs the server's (slice 2); `install` and `reset` swap whole snapshots.
- `InventorySummary`: `count(Group)`, `has(Group, n)`, `hasTool(kind, tier[, maxTier])`.
- Migrated by meaning: `logistics/ChestOrganizationPolicy` (categories by group), `progression/` (logs by
  `#minecraft:logs`, planks by `#minecraft:planks`, pickaxe, sword and hoe checks by tool kind and tier),
  `idle/IdleObservationController` (trinkets: `#minecraft:saplings` plus a kindred group).
- Moved to `VanillaIds` constants, behaviour unchanged: every other `minecraft:` literal in core's main sources,
  except those below.
- `VanillaIdsLiteralTest` (new) with `f38-literal-baseline.txt`: a file may not gain a literal, an unlisted file may
  hold none, and a file that lost some must have its line lowered.

Not touched, by claim (Active work): `factions/SafeZones` (2), `factions/Territory` (2), `market/MarketTable` (1);
they stay in the baseline until FACTIONS A's claims end. Also not touched: `record/`, `rescue/`, `wire/`,
`chronicle/`, `knowledge/`, `match/MatchRegistry`, NativeNavigator and movement (none held literals).

Dependencies satisfied: none needed.
Schema/configuration changes and migration coverage: none. No saved key, NBT or SQL field changed.

## Remaining limitations and handoff

Slice 2 (adapter, `claude/refactor-tags-1109-2`): `KindredCapabilities` builds the snapshot from the server's
item tags (block tags where no item tag exists) and each tool item's class and material, on the server thread at
`SERVER_STARTED` and after each successful datapack reload, and clears it at stop. The progression craft's plank
fallback tries vanilla's woods in the old order, then any other `#minecraft:planks` member by id (on vanilla that
adds crimson and warped planks, the widening noted above).
