# F-19b — Optional Claude strategist

Date: 2026-10-20
Agent / branch: Claude, `claude/modest-faraday-r3spro`
Build: the commit that adds this file (strategist, native fixtures and docs), tested as an uncommitted working tree on top of `ffbb4c4`
Status: in progress (live comparison runs remain)

## Scope and implementation

User-visible behavior: with `KINDRED_STRATEGIST=on` and `ANTHROPIC_API_KEY` in the server's environment, an AI player with the Nether goal consults a Claude model (default Claude Haiku 5.5) when something changes. The model picks how careful the player should be for the next five minutes and may name places to avoid. The local plan still plays every moment. Each player keeps a memory file for each world. Without the switch, or on any failure, play is unchanged.

Changed modules/files:
- `companion-core/.../survival/StrategyAdvice.java`: the advice contract and its validation. A stance from a fixed set (`PRESS_ON`, `PLAY_SAFE`, `SURFACE_AND_RECOVER`) or no advice at all; at most three places to avoid, each within 24 blocks of a place the player reported; reason and note trimmed to one plain line of 240 characters.
- `companion-model/.../ClaudeStrategist.java`: transport through the official Anthropic Java SDK (`com.anthropic:anthropic-java:2.75.0`, pinned in the manifest).
  - The reply is constrained by structured output to the `Reply` record (stance enum, reason, note, places).
  - Planning-lane bounds: a fifteen-second deadline, no retries and 1,000 output tokens.
  - It runs on its own daemon thread.
  - The key is read from the environment only; it is never stored or logged.
- `companion-server-adapter/.../StrategistBridge.java`: when to ask and what it may cost.
  - Triggers: the goal starting, a death, a stage change, a no-progress spell (at most one consultation about those every two minutes), or five minutes with changed progress. At least 20 s apart per player.
  - Concurrency: one request in flight per player, one at a time in all.
  - Rates: six a minute per player, twelve in all.
  - Daily token budgets per player and in all: 50,000 and 100,000 by default, set by `KINDRED_STRATEGIST_PLAYER_DAILY_TOKENS` and `KINDRED_STRATEGIST_DAILY_TOKENS`.
  - Reservation: the conservative input estimate plus the maximum output is reserved before a request and settled to the reported usage. A failure without usage keeps its reservation.
  - The reply is applied on the game thread, and only to the same goal that asked.
- `companion-server-adapter/.../ModelContextStore.java`: one JSON file per player per world at `<world>/kindred/model-context/<player UUID>.json`. It holds the last 20 notes, deaths (place, cause and stage) and pieces of advice, plus consultation and token totals. It is read and written on its own thread, and each write replaces the file whole through a temporary file.
- `companion-server-adapter/.../PortalRunCampaign.java`: the strategist section.
  - An event log of deaths, watchdog moves, stage changes and new danger zones, and the death history.
  - `strategyReport`: the compact report the model sees.
  - The stance in force for five minutes, and its effects:
    - `PLAY_SAFE` skips caves and is outmatched four health points sooner.
    - `SURFACE_AND_RECOVER` climbs out to daylight (walking back or a staircase), heals to 18 there, then turns into `PLAY_SAFE` for the rest of the five minutes, so it does not climb out again.
    - Advised places become danger zones for a quarter of a day.
- `companion-server-adapter/.../PlayerRuntime.java`: constructs the bridge, ticks it after each goal step, passes the death message on as the cause, closes it on stop, and adds `adviseGoal` (used by fixtures).
- Build: `companion-model` depends on the SDK. The adapter depends on and includes `companion-model`. The release jar does not yet carry the SDK; with the switch on there, a `LinkageError` is caught and play goes on without the strategist.

Dependencies satisfied: F-19a (companion-model module), F-25c4 (the goal it advises).
Schema/configuration changes and migration coverage: no SQLite or NBT change. The context files are new, per world, and may be deleted. New environment switches are listed above.
Requirements and AT portions covered: AI-01 (optional, operator key, off by default), AI-02 (no code, permissions, items or completion; model text is data), AI-03 (strict schema and validation; the reply is applied only to the goal that asked), AI-04 (meaningful changes only; local work continues while a reply is pending), AI-05 (planning lane deadline, rates, concurrency, reserved budgets). The reply is a stance, not a one-to-six-step plan, so there are no steps to revalidate at dispatch.

### Live runs

The runs below are development runs on seed 8675309, one AI player from an empty inventory. They are not a release gate.

- Run 60 had no strategist. It ran on `ffbb4c4` for 32 minutes and is the baseline.
  - Five deaths: a zombie, drowning, a creeper, a skeleton and a pillager.
  - Gear: an iron pickaxe within three minutes, then two buckets, a chestplate and a shield.
  - It was still at the iron stage when stopped. Six iron pickaxes were made, worn out or lost in deaths.
  - The drowning came while every goal step was cancelled by the urgent retreat, underwater.
- Run 61 had the strategist on (`45c40c0`), for 18 minutes.
  - The first three consultations, at the goal start and at the stone and iron stages, said `PRESS_ON`. Each was 1,199 to 1,429 input and about 100 output tokens. The player's context file was written after the first reply.
  - No deaths, the first run on this seed without one since run 53.
  - Gear: the iron pickaxe within two minutes, then a shield, both buckets and the chestplate.
  - It stalled at the iron stage, fetching water from below a lake: 1,202 refused walks (fixed since in F-25c4).
  - 17 consultations: 12 `PRESS_ON` and 5 `SURFACE_AND_RECOVER`.
    - The second stance came below ground at night with no food carried and many no-progress spells. At night the stance only raises the heal threshold, as the player does not climb out in the dark.
    - Its reasons named the real problem ("repeated no-progress spells at the water fetch ... call for switching targets rather than a change in caution"), which no stance can fix.
  - 34,957 input and 6,338 output tokens, about $0.007. Replies came back within a few seconds; play did not wait for any of them.
- Run 62 (strategist on, with the pool fix), 21 minutes.
  - Two deaths in the first three minutes: a zombie in the cave under spawn at night, then a creeper.
  - After the first death the strategist advised `SURFACE_AND_RECOVER` and named the death cave and two danger zones near it to avoid. After respawning on the surface it said `PRESS_ON` while "staying out of that cave".
  - By 13 minutes: the iron pickaxe, buckets, chestplate and shield, with no further deaths. At 19 minutes it suffocated while digging by hand with no pickaxe left.
  - 24 consultations: 8 `PRESS_ON`, 14 `SURFACE_AND_RECOVER` and 2 `PLAY_SAFE`. 52,640 input and 10,257 output tokens.
- Sky-island runs had the strategist on as well.
  - Run 5 went four `PRESS_ON`s in about two minutes; it blocked on a cast fixed since (F-25c5).
  - Run 6 waits on saplings for logs, and at night ran out of food with none left on the island.
    - The strategist said `SURFACE_AND_RECOVER` with reasons such as "finding food comes before more log searching". The player was already on the surface, and no stance makes it find food.
    - Because no-progress spells came every few seconds, it was asked every 20 s with the same answer. Fixed since: a no-progress spell prompts at most one consultation every two minutes.
    - 21 consultations in 13 minutes, 46,151 input and 5,927 output tokens.
- Totals for these runs and the two live API tests: about 142,000 input and 24,000 output tokens, about three cents.

What it shows: the strategist reads the reports correctly, is cheap and never holds up play. Its advice helps where the levers fit (staying out of a cave that killed the player, climbing out hurt in daylight). The problems it names most often are progress stalls and missing food, which the stance cannot address: it needs a lever for what to do next (for example, food first), not only how carefully.

### Closer to real time (2026-10-21)

The strategist was made fast enough to follow play rather than check in every few minutes.

- Measured with `ClaudeStrategistLiveTest.paceBenchmark` (opt-in, `KINDRED_LIVE_MODEL_BENCH`): the same hunger report, four calls at each setting.

  | Setting | Time per call | Output tokens | Advice |
  | --- | --- | --- | --- |
  | Model default (medium effort, adaptive thinking) | 2.8–4.0 s | 417–573 | `SURFACE_AND_RECOVER`, food first, `MORE_FOOD`, every time |
  | Low effort, thinking on | 2.0–3.0 s | 335–455 | the same |
  | Low effort, thinking off | 1.9–2.0 s | 156–172 | the same |

- Low effort without thinking first is now the default (`KINDRED_STRATEGIST_EFFORT`, `KINDRED_STRATEGIST_THINKING` change it). An earlier run of the benchmark without caching gave the same ranking.
- The instructions and reply schema are cached: 1,645 of the 1,974 input tokens were read from the cache from the second call on. A question now costs about $0.00013.
- Pace (`KINDRED_STRATEGIST_PACE`):
  - Steady (the default) keeps the cadence and AI-05's default budgets above.
  - Real time asks as often as the planning lane allows (ten seconds apart per player at most, six a minute), and about a no-progress spell every 30 s, and otherwise every minute while progress changes.
  - Real time also asks whenever the goal reports something new: a fight with a new foe, a hit that costs six health or more, nightfall or daybreak. These are logged as events in the report.
  - Its advice holds for 1,200 ticks (a minute of game time) unless renewed.
  - Its default budgets are 5,000,000 tokens a day per player and 10,000,000 in all.
- Each reply's log line now gives the cached tokens and the time it took.
- The live runs for this play at the normal 20 ticks a second instead of `/tick sprint`, so a minute of play is a minute of real time.
  - Run 64 (the working tree that became `349c270`, before its fight log line; about 16 minutes): no deaths. Six replies in its first 13 minutes, median 1.34 s, worst 3.3 s (the first call, on a cold connection).
  - Run 65 (`349c270`, 22 minutes): no deaths, the iron pickaxe at about six minutes. 24 replies, median 1.46 s, 90th percentile 1.9 s, worst 4.3 s. Each reply read 1,644 tokens from the cache.
  - Run 66 (`468e1e7`, the first 38 minutes): no deaths. 45 replies, median 1.55 s, 90th percentile 2.0 s, worst 3.3 s (the first call). 136,634 input tokens, 73,980 of them from the cache, and 7,112 output. When a skeleton took it to 12/20 below ground at night, the reply ("surface and recover") came 1.5 s after the hit, while the fight was still on.
  - Sky-island run 12 (`468e1e7`, 40 minutes): 29 replies, median 1.34 s, 90th percentile 1.9 s. It asked for wood first 28 times while the player was stuck exploring for a log it could not reach, which no advice could fix ([F-25c5](F-25c5.md), fixed since).
  - In calm daytime play it asked about once a minute, as the period allows. Fights and heavy hits make it ask sooner.
- What run 66 showed about memory at the real-time pace, found at 67 minutes (no deaths in the run):
  - Every reply wrote a note, and all twenty kept notes were the same lesson reworded ("Hurt and hungry below ground keeps repeating; surface, eat and heal before any tunnelling..."), which would push out any other lesson. Fixed since: a lesson already noted is kept once however it is worded ([F-19c](F-19c.md)). The instructions now say to write a note only for a lesson the notes do not hold yet.
  - The habit it taught, `SHELTER_EARLY`, came with the note "Hungry and hurt underground at night has been fatal again and again", in a world with no deaths. The low health was real, for many minutes, but the deaths were not. The instructions now also say to state in a note only what the report shows, never a death, place or event it does not list. The text cannot be checked in code; the habit itself is still one of the four fixed names.
  - Sky-island run 13 (`21b8dbf`, also before the fix) kept ten notes that were three lessons ("smelting stalls without fuel: gather logs and coal..." seven times); the new rule keeps three. Its 29 replies took a median 1.40 s, 90th percentile 1.94 s, worst 2.9 s, with 81,127 input tokens (47,676 cached) and 3,729 output. It said wood first 22 times while the player waited on saplings for fuel, which no advice could hurry. The player built and lit the portal with no deaths ([F-25c5](F-25c5.md)).
  - The two opt-in live tests passed again with the new instructions. The repeated-hunger report still brought food first and `MORE_FOOD`, with the note "Two deaths followed running out of food below ground; carry food and eat before going down to mine iron." (2,018 input, 1,689 of them cached, and 161 output tokens; 2.4 s).

- One run each with and without it is not a comparison: run 61 had no deaths and run 62 two, against five in run 60, on builds that also differ.
