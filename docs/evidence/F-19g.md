## Scope and implementation

RUNNER 2's keyed run f34c2-37adcdc spent its model tokens on Chronicle pages. Its page calls logged no token or cache
counts, so no run could show whether the prompt cache works (F-19f). The lead approved a log-only fix, which the
freeze allows (2026-11-15).

**The change:**
- `Strategist.Outcome` (the stance), `Line` (the voice) and `Page` (a Chronicle page) gain `cacheWriteTokens`:
  - `NOT_REPORTED` (-1) where the provider does not report it;
  - a constructor in the old shape, so nothing else changes;
  - `withCacheWrite`.
- `ClaudeStrategist` sets the write from `usage.cacheCreationInputTokens()` on the stance, voice and page calls. The
  input total is unchanged: it already counted the write.
- `ModelUsage.line` (new) gives a call's usage as
  `in N, cache read R, cache write W, out O tokens, M ms`, the write "n/a" when not reported.
- `StrategistBridge` logs one INFO line a call, whatever its outcome:
  `<name> strategist call: …`, `<name> voice call: …`, `<name> chronicle call: …`.
  The voice's re-check of a provider's line keeps its write.
- The existing lines (the stance's advice, the said line, the page kept or refused) are unchanged.
- The operator guide says what the line means.

**Found on the way, not changed** (the lead's word: not worth padding):
- A Chronicle page cannot be cached as built. `ChroniclePrompt.SYSTEM` is about 200 tokens, under the 512-token minimum
  a prompt cache needs, and the page request sets no cache marker.
- So "cache read 0" on every page is by construction, not a cache failure.
- The stance prompt (about 2.5k tokens, marked) stays F-19f's to measure with these lines.

Not body behaviour: log lines and the records' extra figure.
