# E-10d — The starters begin with their own personalities

Date: 2026-10-29
Agent / branch: Claude / claude/loose-ends-1029
Build: `21a8a3d`
Status: complete

## Scope and implementation

User-visible behavior:
- A starter made with `/aiplayer roster spawn` now begins with the personality `CanonicalRoster` gives it: Kindred helpful, sociable and a farmer; Sol bold and combative; Echo curious, careful and a miner.
- Before, all three began with every trait at 50, so they differed only in name and skin (loose end C13).
- Once made, the personality is the player's own: its operator may change it, and spawning the starter again reconnects the saved player without resetting anything.
- A starter saved before this change keeps what it has.

Changed files:
- `SocialProfile.withPersonality` (core, with `SocialProfileTest`).
- `PlayerRuntime`:
  - `createNative` takes an optional preset, applied in the creation callback before the body connects. It is saved with `store.saveProfile` and the expected revision, as every profile change is; a failed save faults and stops the player, as a failed profile change does.
  - `spawnCanonicalRoster` passes each starter's preset.
  - A fixture accessor.

Saved data: no schema change. The preset is an ordinary profile write (revision 1) to the profile row the store already creates for a new player.
