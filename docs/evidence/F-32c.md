# F-32c — The knowledge web's start-up read at a month's scale

Date: 2026-11-15

Build: the branch's head (see the PR)
Status: complete (diagnostics and a test; no behaviour change)

## The question

At every start the knowledge web is rebuilt from the World Record (F-32b). `PlayerRuntime` asks the ordered writer for
every event of the web's kinds (claim, unclaim, capture, correction, message), then replays them on the server thread.
A month's Record grows by about 13,000 events a game day, mostly journal and action events (RUNNER 2's f34c3-37adcdc).
So does that start-up read, or the replay, grow with the month?

## What was measured

| Check | Result |
| --- | --- |
| The web's kinds in a keyed Factions run (f34c3-37adcdc, its cost lines) | 7 `message` and 3 `claim` events in 4 game days, against 52,874 events in all |
| The read (`kind IN (…)`, ordered by id, in pages of 5,000) on sqlite-jdbc 3.50.3: a 3,000,000-event Record on disk (601 MB) written through the store, 750 of the web's kinds among it | 2–5 ms, three runs. Plan: `SEARCH world_events USING INDEX world_events_by_kind (kind=? AND id>?)` |
| The same after `ANALYZE` | 2–3 ms, three runs, the same plan |

So the read follows the kind's index and grows only with the web's own kinds, not with the Record. A first check in
Python's sqlite 3.53.1, on a sample with different statistics, walked every event (`rowid>?`). That is not what the
project's driver does with the Record's data, and the store is unchanged.

## What changed

- `PlayerRuntime`: one start line, `Knowledge web rebuilt from the Record: N events, read in R ms on the writer,
  replayed in P ms; the world's web W relations, A AI players' webs holding H`. The read is timed from asking, so the
  writer's queue at start is included. With this line, a month run's restarts show whether either side grows.
- `SqliteCompanionStore.worldEventsPlanForTest`: the plan of that read, for the test below. Test-only; the read itself
  is unchanged.
- `WorldEventsByKindStoreTest` (new, 2):
  - the web's kinds come back whole and in the Record's order across the 5,000-event pages (14,000 of 40,000
    interleaved events), and a page after an id gives the next events;
  - the read searches `world_events_by_kind`, with and without statistics, and never walks every event.

  If a later change to the schema or the query lost the index, this test fails rather than a month run's start
  slowing.
