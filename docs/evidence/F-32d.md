## What was asked

The lead asked for this on 2026-11-16, from Session B's month-scale audit:
- index the open relations, so `KnowledgeWeb.add` does not walk every fact it holds;
- show 80,000 adds in linear time;
- show the same relations as today's code on the same inputs, comparing both;
- say whether told facts escape `bound()`'s 20,000, and whether that is acceptable at the month's estimate;
- add each AI's web fact counts to the month run's health report.

## Before

`add` copied the whole web and scanned it on every call, to end the same fact already open. That makes n adds
quadratic. The audit measured it on main:

| Adds | Time |
| --- | --- |
| 5,000 | 0.4 s |
| 20,000 | 7.7 s |
| 40,000 | 44 s |
| 80,000 | 176 s |

`bound()` walked the web from its oldest fact whenever it held more than 20,000. A web full of facts that never lapse
was walked whole on every add.

## The change

`KnowledgeWeb` keeps two indexes beside its relations, updated by one `put` that every change goes through (`add`,
`confirm`, `end`, `correct`, `bound`):
- **The open relations**, by subject, verb, object, visibility and group, then by when each lapses. `add` ends only
  those lapsing after its tick, the same test as before (`until > tick`), found in the index.
- **The relations that lapse**, the only ones the bound can drop, in id order. That is the web's own order, since ids
  rise as facts are added and the map keeps insertion order. The bound walks these alone, oldest first, and stops at
  the same size, so it drops what the old walk dropped.

Two edges are kept as they were:
- **A fact with no object** replaces nothing. Its object is stored as "", which never equalled the `null` it was asked
  with.
- **At the last tick there is** (`Long.MAX_VALUE`), even an open fact has lapsed. The bound walks the whole web then,
  as before.

`end` still tests its predicate against every fact. It is called on the Record's ends of claims, not on every message.

## The comparison

`KnowledgeWebIndexTest.theIndexedWebHoldsExactlyWhatTheWebBeforeItHeld` runs `KnowledgeWebBefore`, a test-only copy
of main's `add`, `confirm`, `end`, `correct` and `bound` at 039c8b9.

- **12 seeds of 6,000 random changes each**, made to both webs:
  - 80% adds, from a small pool of subjects, objects and groups, so the same fact comes again; with every verb, every
    kind of knowing and four visibilities; some with no object and some with no group;
  - confirmations, ends and corrections;
  - ticks mostly rising, and one change in twenty going back.
- **Bounds:** 300, 3,000, or one no web reaches. The bound is a test-only constructor parameter, so the bound is
  crossed in a fast test. Production uses 20,000.
- **Compared:** the relation each add returns, and every change's result. Every 500 changes and at the end, every
  relation in order, field for field (the records' equality).
- **Kept for good:** the count the bound can never drop equals the count from the web before.

Mutations, each run once:

| Mutation | Result |
| --- | --- |
| The no-object edge removed | fails |
| The bound's lapse test made strict (`<` for `<=`) | fails |
| Facts lapsing before tick 5,000 left out of the bound's index | fails (the timing test's counts) |
| The index's tail made inclusive (`until >= tick`) | passes |

The inclusive tail passes because it can't be seen: it rewrites a fact ended at that same tick to the same values.

`eightyThousandAddsTakeTimeLinearInTheirNumber`:
- **The workload:** told facts at the real bound of 20,000, each its own, every hundredth told again.
- **Timing, best of three after a warm-up:** 20,000 adds in 4 ms, 80,000 in 21 ms. The code before took 7.7 s and
  176 s. The test asserts at most eight times the 20,000 figure (linear is four, the code before sixteen).
- **What stays:** 79,200 relations. The 800 facts told again end the 800 before them, and those are the only ones the
  bound drops.

## Told facts and the bound

**Yes, told facts escape the bound.**
- A fact told on the Wire (anything but a sighting or a claim) holds until it is replaced or ended, and `bound()`
  never drops an open fact or a correction.
- So a web can hold more than 20,000. The test above holds 79,200.

**Acceptable for the month run, on the estimate.**
- **The estimate:** about 43,000 facts a month across all the webs, from the measured rate (7 message events in 4 game
  days, f34c3-37adcdc). With 8 AI players that is about 5,400 a web.
- **What stays for good is lower still.** A fact told again (the same subject, verb, object and group: a store's
  count, a claim, a place) ends the one before, and the ended one lapses and can be dropped. Only distinct open facts
  and corrections stay for good.
- **Cost:** the index makes a large web cheap to add to. The memory is one relation and two index entries a fact.

The estimate is not a measurement, so the cost line now carries each web's counts (below). The pre-flight report
warns (WATCH) when a web keeps more than 20,000 for good.

**A bound, if the month's counts show one is needed** (proposed, not made; it would change what is known):
- drop open told facts never confirmed and not told again for 30 game days, oldest first, over a web's 20,000;
- never drop a recorded fact, a correction, or a fact about the web's own player;
- each told fact stays in the Record as the Wire delivery that told it, so an audit can still read what was dropped.

## The health report

The daily cost line (`Kindred cost: day N: ...`) gains each AI's web, by name, as relations held and kept for good:
`; webs by player, held/kept for good {Ada=120/80, Bram=95/60}`. A web with no live player is named by its id's first
eight characters.

`tools/soak/preflight.py`:
- prints each day's webs;
- prints each web's facts kept for good per game day between day lines, for players in both lines;
- warns (WATCH) when a web keeps more than `KnowledgeWeb.MAX_RELATIONS` (20,000) for good. That threshold is set in
  code, not guessed.

`NativeCostGameTests.theCostLineCountsWhatTheRecordWrote` checks the line. The player's web is told three facts, one
of them twice, and the line reads `{<name>=3/2}`.
