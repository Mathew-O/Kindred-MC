## Scope and implementation

This change is to the fixture only; no product code changes.

`NativeAutonomyGameTests.scopedLogIsAutonomouslyMined` failed on #139's run 42793316263 and on #137's run 42793187025
(attempt 2), on PRs whose diffs do not touch mining. From both logs, all in the same second:
- `native_mine COMPLETED [from patchMineCandidates]`;
- the patch mine's settle-wait for the falling drop, and "mined out its patch: 1 oak log";
- `native_craft COMPLETED [from evaluateScheduledRoutineCandidates]`, its routine making planks of the log.

The test read the activity's latest work and the latest action record once its seven empty steps had passed. Once the
craft had run, both were the craft's for good, and the step could never pass however long it retried. Crafting after a
mine is the player's own autonomy, not a fault.

The test now takes each fact on the tick it shows, through `runAtEveryTick`, and checks it at the end:
- its work "Completed native_mine", with time charged to the paid activity on that tick (`chargedMillis > 0`);
- its record a verified `native_mine`, and exactly one verified `native_mine` seen, so the log is mined once;
- the log broken, and the axe worn once, as before.

The check no longer pairs "Completed native_mine" with an IDLE phase. Completing the mine stops the activity, and in the
same server tick the patch mine's settle-wait starts the next work. So IDLE with "Completed native_mine" is never visible
at any tick boundary: in 1 local run of 6 it was never there. The verified record shows the completion. The lead accepted
this as the full check; the test's comment says why.

A copy, `scopedLogIsAutonomouslyMinedReadAfterItsNextTask` (batch `autonomyMineThenMore`), reads only once a task other
than the mine has run since. It forces the form CI saw.
