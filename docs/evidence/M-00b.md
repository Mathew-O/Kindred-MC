## Scope and implementation

M-00 asks for a match's presentation: titles, a boss bar, the action bar, a scoreboard, sounds and particles, all visible without the client mod. This slice shows a duel (M-00a) to the players in it with what a vanilla client shows unaided:
- **A boss bar.** The players and the clock: "Duel: Ada vs Bram - 4:32", emptying as the time runs out. It is yellow through the lobby and countdown and red once the fight runs. A player who joins the server mid-match gets it; a player who leaves is dropped from it. It is taken down when the match ends, and every bar is taken down when the server stops.
- **Titles with sounds.**
  - The countdown: "3", "2", "1", each once, on its own second whichever tick it starts on, with a note block's ping.
  - "Fight!" as it begins, a higher ping.
  - Each player's own result: "Victory" (a challenge's chime) or "Defeat", with how it ended ("Ada won: Bram fell").
  - Or, with no winner: "Draw" when the time ran out, "Stopped" for an operator's stop, "Called off" for a player leaving before the start.

What to show is worked out in core (`MatchPresentation`), apart from how it is sent, and tested there. The adapter's `MatchPresenter` sends it: title packets, a `ServerBossBar` and sounds to that player only. It keeps the last eight titles shown to each player, for fixtures to read back.

Changed modules/files: `MatchPresentation`, `MatchPresentationTest` (core, new); `MatchPresenter` (new), `PlayerRuntime` (the presenter on the tick, on each change of state, and on stop); `NativeMatchGameTests` (the duel's presentation checked).
Dependencies satisfied: M-00a.
Schema/configuration changes and migration coverage: none.
