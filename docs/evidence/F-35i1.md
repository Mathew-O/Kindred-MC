## Scope and implementation

`NativeFactionBackOffGameTests.aFactionWalkRefusedBetweenItsGoalsTasksIsBackedOffEachTime` failed once in B's M-06k5
narrowed runs: "9 refused, 8 counted", on a claim move. Its check was that every refused faction walk is counted by
the back-off. It counted the refused walks in `blockedWalks`, and the back-off's own count in `refusalsCounted`. The
back-off counts a refusal only while the walk's move is still the current one.

The missing one was not a refusal the back-off missed. `factionCandidates` settles a move while its walk may still run,
in three places:
- **There:** the player stands in the move's chunk (`arrived`). A claim or capture is asked from where it stands.
- **Set aside:** the place is already set aside.
- **Open water:** the walk's end is seen to be open water. The place is set aside there and counted toward the streak
  (F-35j1).

Each of the three already accounts for the place. The walk's refused end that follows is no refusal of a move still to
be made.

From B's log of the failing run (main a6e7ffc with M-06k5's change, which cannot reach this test):
- The 4th of Ada's nine refused walks was to -4776541, -11068900, in chunk (-298534, -691807).
- In that same tick it captured that chunk from Blue, from where it stood gathering logs on the chunk's west edge.
- So the capture move was settled as "there" while its walk ran. The walk then came back refused, counted in
  `blockedWalks` but not by the back-off.

The fix is in the fixture's check. What the player does is unchanged:
- `FactionsPlayer` gains `blockedSettled` and `settledWalk`.
- `PlayerRuntime.settledInFlight`, called at the three places a move is settled, notes the walk's task id. It does so
  only when that walk is the current task.
- A refused faction walk with that task id adds one to `blockedSettled`.
- The fixture asserts refused = counted + settled, so a refusal the back-off loses any other way still fails it. The
  failure names all three counts.

No decision path reads these. `settledWalk` is read once, to add to `blockedSettled`, and cleared when the faction walk
ends. `blockedSettled` is read only by `factionBlockedForTest`, the fixture's own call.

Changed modules/files:
- companion-server-adapter: `FactionsPlayer` (two counters), `PlayerRuntime` (`settledInFlight`, the faction walk's
  end, `factionBlockedForTest`).
- gametest: `NativeFactionBackOffGameTests` (the check).
- docs: this file, `feature-spec.md`, `validation.md`.
