## Scope and implementation

`run.py --keep-world` kept a run's region files and its companion database, and deleted the rest of the world. So a stuck place could be staged from its own ground, but not with what its player carried.

e40c3's two Nether stalls show the gap:
- 303's blaze fight;
- 8675309's reconciliation hold.

The database holds no inventories, because physical items live in the players' native saves. The only record left was each player's last replay, which was from the Overworld, before the trip.

Now a kept world also has `world-kept/playerdata/<uuid>.dat`:
- **Whose:** one save for each player the run's `eval-result.json` names, matched to its id by the server's `usercache.json`.
- **When it can't match:** if either file is missing or unreadable, every save in `playerdata/` is kept. An evaluation server has no other players.
- **What is left out:** `.dat_old` backups.

Changed files:
- `tools/eval/run.py`: `finish` and `run_player_ids`, and the `--keep-world` help;
- `tools/eval/test_eval.py`: `KeepWorldTest`, three tests;
- `tools/eval/README.md`.

There are no schema, configuration or product changes, and nothing the players see is read from the kept files.
