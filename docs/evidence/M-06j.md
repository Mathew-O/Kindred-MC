### A fresh server built from the manifest (2026-11-08)

Linux x64, 4 cores, 15 GB, OpenJDK 21, `-Xms2G -Xmx3G`. An empty directory was used. A script followed the README's
install steps:
- each mod downloaded by the index's own link and checked against its SHA-512, SHA-1 and size;
- the Fabric server launcher for 1.21.1 and Loader 0.19.5 (installer 1.1.2) from meta.fabricmc.net;
- the Kindred jar;
- the pack's `server.properties` and `config/kindred/factions.properties`.

Extrapolated, not measured: the full overworld at radius 4,000 (about 250,000 chunks) is about 1 h 50 min at that rate on
four cores. The owner's 12 GB machine is to be timed on the day.

Textile Backup's own config, written on its first start, was read. The keys are `backupInterval` (seconds),
`backupsToKeep` and `shutdownBackup`. `config/textile_backup.json5` is now in the pack as written, with three values
changed:
- every 3 hours (`backupInterval: 10800`);
- the last 16 kept (`backupsToKeep: 16`);
- backups also on an empty server (`doBackupsOnEmptyServer: true`), since AI players play with no person online.

`spark heapsummary`, run during the proof, uploads its summary to spark's public paste site by default. That summary was
of this scratch server only, with class counts and no world data or keys. The operator guide should say to use
`spark heapsummary --save-to-file` on the owner's server.
