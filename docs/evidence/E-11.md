# E-11 — Shared projects and AI-player task assignments
Date: 2026-10-18 EDT; report 2026-10-18.
Antigravity / uncommitted main, no commits. Complete for this feature.

## Scope and implementation
User-visible behavior: Multi-agent cooperative project coordination and AI-player task assignments. Autonomous AI players coordinate work across shared multi-step projects with strict dependency tracking, single-assignee ownership, material reservations against shared stock, contention handling, automatic revocation upon player death or stop, periodic lease expiration, and durable SQLite persistence (Schema 8) with crash recovery. AI players collaborate on team goals without duplicating assignments or double-spending shared resources.

Changed modules/files:
- `companion-core`:
  - `dev.kindred.core.team.ProjectId`: Strongly-typed project identifier.
  - `dev.kindred.core.team.TaskId`: Strongly-typed task identifier wrapping UUID.
  - `dev.kindred.core.team.StockReservation`: Material reservation record with destination, item, count, and reservation status (`ACTIVE`, `FULFILLED`, `RELEASED`).
  - `dev.kindred.core.team.StockLedger`: Pure material ledger tracking total stock, active reservations, unreserved available counts, and atomic reservation/fulfillment/release.
  - `dev.kindred.core.team.SharedTask`: Task definition record supporting dependencies (`Set<TaskId>`), single-assignee ownership (`UUID assignedPlayerId`), states (`OPEN`, `CLAIMED`, `IN_PROGRESS`, `COMPLETED`, `REVOKED`, `FAILED`), material reservation (`Optional<StockReservation>`), lease timing, and completion evidence.
  - `dev.kindred.core.team.SharedProject`: Container record managing task maps, overall project state (`OPEN`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`), and project-level completion checks.
  - `dev.kindred.core.team.TeamCoordinator`: Thread-safe coordination engine providing project registration, dependency satisfaction discovery (`findEligibleTasks`), atomic single-claim assignment with contention rejection (`claimTask`), task startup (`startTask`), task completion with evidence recording and stock fulfillment (`completeTask`), revocation (`revokeTask`), fail-safe death and stop settlement (`handlePlayerDeath`, `handlePlayerStop`), and lease expiry sweep (`handleTickExpiry`).
  - `TeamCoordinatorTest.java`: 7 pure unit tests verifying dependency ordering, single-assignee contention rejection, stock reservation double-spending prevention, death and stop revocations, lease expiry recovery, and project completion transitions.
- `companion-persistence`:
  - `V8__shared_projects.sql`: Additive database schema migration adding `shared_projects`, `shared_tasks`, and `stock_reservations` tables with foreign keys and indices.
  - `SqliteCompanionStore.java`: Upgraded schema version range to 8, registered V8 migration, added startup crash reconciliation (automatically releasing active in-flight reservations and resetting claimed/in-progress tasks to `OPEN`), and implemented asynchronous persistence methods (`createProject`, `saveProject`, `saveTask`, `saveReservation`, `findProject`, `listProjects`).
  - `SharedProjectStoreTest.java`: 4 persistence unit tests verifying project/task round trips, project revision optimistic locking, task revision optimistic locking, and startup crash recovery.
  - `SqliteCompanionStoreTest.java` and `NativePlayerStoreTest.java`: Updated schema rollback tests to cleanly drop Schema 8 tables.
- `companion-server-adapter`:
  - `PlayerRuntime.java`:
    - Added `TeamCoordinator teamCoordinator` instance and public accessor.
    - Integrated team task candidate evaluation in `evaluateScheduledRoutineCandidates` at `Priority.PROJECT` (need 68.0), prioritizing held tasks or eligible unassigned tasks.
    - Wired atomic task claiming and starting in `beforeNativeTick` upon task proposal dispatch.
    - Handled task completion with blocker evidence and stock consumption in `observeRunner` on `SkillRunner.State.COMPLETED`.
    - Handled task revocation and reservation release in `observeRunner` on `BLOCKED`, `CANCELLED`, or `PAUSED`.
    - Handled player stop revocation in `halt(Entry, Actor, String)`.
    - Handled player death revocation in `entityDied(CompanionEntity)` and in `beforeNativeTick` when `!body.entity().isAlive()`.
    - Added periodic `teamCoordinator.handleTickExpiry(tick)` invocation in `onServerTick`.
    - Asynchronously loaded existing persisted projects on startup via `store.listProjects()`.
  - `NativeTeamGameTests.java`: 4 Fabric acceptance GameTests testing cooperative task dependency ordering across peers, single-assignee contention rejection, shared stock reservation preventing double-spending, and player stop/death revocation.
  - `fabric.mod.json`: Registered `dev.kindred.fabric.NativeTeamGameTests` under `fabric-gametest` entrypoints.
