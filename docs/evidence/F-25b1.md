## Scope and implementation
NativePlayerBody implements the existing BodyAdapter and binds exactly one ActionArbiter. Its entity subclasses ServerPlayerEntity, uses vanilla player inventory/equipment, interaction manager, hunger, timed food consumption, physics and fall handling. No copied equipment, direct healing, instant survival block-breaking, separate action arbiter or persistence writer was introduced. Only the existing server-thread world boundary handles native objects.

Inputs carry an exact current ActionLease. A required MutationGate checks activity, policy, revisions/claims and the authorized target; native checks add survival/alive state, loaded chunks, reach, obstruction and unchanged selected block. Timed operations recheck before native tick mutations. Stop clears voluntary input, digging and food use synchronously. A backend construction requires an explicitly mapped body UUID and rejects loaded/connected collisions; its stable internal profile has no operator permission.

The backend is deliberately unregistered. It neither replaces a saved mob nor connects through PlayerManager, provisions accounts, writes player files, adds commands or enables autonomous work. Those lifecycle steps require the rest of F-25b and F-25c admission. The factory does not assert durable uniqueness between unregistered instances; runtime registration/reconciliation must enforce that before activation.
