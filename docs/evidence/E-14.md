# E-14 — Bounded expeditions, exploration and return planning

## Scope and implementation

User-visible behavior:
Autonomous AI players can plan, execute, and backtrack bounded exploration expeditions:
- Track discovered points of interest (`WaypointKind`: `HOME_BED`, `SHELTER`, `RESOURCE_PATCH`, `WORKSTATION`, `HAZARD`, `LANDMARK`, `BREADCRUMB`) with 3D coordinates, dimension, timestamp, and Euclidean distance calculation.
- Evaluate expedition readiness before departure: requires healthy status ($\ge 14.0$ HP), sufficient edible food rations ($\ge 2$ items), daytime and clear weather, and inventory capacity ($< 32$ slots occupied).
- Bound exploration outward motion within a configurable maximum distance (`DEFAULT_MAX_EXPEDITION_RADIUS` = 64 blocks, or custom anchor radius) from home base / shelter.
- Multi-factor return trigger evaluation responding autonomously to:
  1. Nightfall and dusk approaching (`tod >= 11500`).
  2. Severe weather (thunderstorms).
  3. Critical low health ($\le 8.0$ HP).
  4. Low rations & hunger ($0$ food items and food level $\le 10$).
  5. Full inventory loot capacity ($\ge 32$ slots occupied).
  6. Maximum expedition radius reached.
- Autonomous return route planning and breadcrumb backtracking routing the player along recorded trail waypoints back toward home anchor via `native_traverse`, with priority elevation (`URGENT` for night, thunderstorm, critical health; `PROJECT` for full inventory, dusk, max radius).
- Arrival detection resetting expedition state to `IDLE_AT_BASE` and clearing return reasons upon reaching base shelter within $\le 2.0$ blocks.
- Shared landmark and waypoint registry via `TeamCoordinator` (`shareWaypoint`, `getSharedWaypoint`, `listSharedWaypoints`) enabling discovery propagation across peer players.
