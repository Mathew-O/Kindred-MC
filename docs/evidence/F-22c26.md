# F-22c26 — The test server simulates chunks around its players as a live server does

Date: 2026-11-08
Agent / branch: Claude / claude/ci-green-1105-sim (CI fully green, F-22), from `0e28e65`
Build: recorded in [validation](../validation.md)
Status: complete (native fixtures)

## Scope and implementation

Root cause, in the fixtures' server, not the product:
- The GameTest server never sets a view or simulation distance, so its player manager keeps 0. Only the chunks next
  to a player tick. A live server's default, in `server.properties`, is 10.
- A chunking probe placed sand in the air at five distances from a player:
  - with simulation distance 0 only the sand 20 blocks off fell; at 40, 72, 120 and 200 it hung;
  - at simulation distance 10 the sand at 40 fell too;
  - with the view distance at 10 as well, the sand at 72 fell.
- The symptoms this explains:
  - a climb that crossed a chunk edge waited for its sand till its test ended;
  - a villager stopped by a chunk's edge;
  - a minecart rolling out of the player's chunk stopped dead.
- Each fixture that needed its ground ticking held it simulated by hand (`FixtureGround.simulated`). One that did not
  failed whenever the grid put a chunk edge in its way. The per-fixture calls are kept.

Changed files (gametest source set only):
- **`GameTestPacing`:** on the test server's start, its player manager's view and simulation distances are set to
  `SIMULATION_DISTANCE`, 10. A dedicated or integrated server is untouched.
- **`NativePlayerBodyGameTests`:** new fixture `sandTwoChunksFromAPlayerFallsAsOnALiveServer`. A player flies 60
  blocks off and 30 up, and sand is placed 100 blocks off (two chunks from the player) over stone. It must fall.
  Fixture staging: the player's position, the sand and the stone are set by the fixture. The player earns nothing.
- **`NativeNavigationGameTests.aBreakLongerThanOnePaidSliceCompletesAtRealTime`:**
  - A fixture bug the change exposed: the test held each tick to 50 ms with a single `LockSupport.parkNanos`, which
    can return early. The server's executor unparks its thread for each task handed to it, and chunks loading around
    a player at view distance 10 hand it many.
  - The fix: it parks again until the 50 ms are up, as `GameTestPacing` and the accounting fixture already do. Its
    message now gives the ticks held. The assertion (more than 6 s) is unchanged.
