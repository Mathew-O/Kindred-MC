## Scope and implementation

This change is to the fixture only; no product code changes.

`NativeTrustGameTests.tossesStopAtSixteenWithTheCapsDayEndingAsTheAsksBegin` (F-22c36) stages the end of a cap's day by
setting the server's tick to 55 before the next day's end. On #139's run 42827017264 (main `53cd517`), reported by
Session A:
- the server was already in that day's last 55 ticks, so the target was behind the current tick, and the tick went
  backwards;
- a runtime still live from an earlier batch refused it in `AttentionWorkScheduler.beginTick`: "Backward tick: 167946 <
  167977";
- the whole GameTest server stopped at the start of batch `trustTossDayEnd`, and every test after it in that run went
  unrun.

The staging now takes the next day's end less 55 that lies ahead of the current tick (`dayEndLess55`): when the current
day's has passed, the one after. It checks that the tick moves forward before setting it. A copy,
`tossesStopAtSixteenWhenTheDayIsAlreadyInItsLastTicks` (batch `trustTossDayEndLate`), first sets the tick to 30 before a
day's end once its player is live, lets a tick pass there, then stages. It also watches the server's tick each tick
and fails if it ever goes back.
