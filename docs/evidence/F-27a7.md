## Found (F-25c6e's gate, 2026-11-23)

`gate.sh` puts each round's runs of every flagged scene into one file a round (`confirm-<side>-i.xml`), and
`report.py` read each `--confirm-*` file as one whole round. F-25c6e's gate was confirmed by hand, and two hand loops
went wrong:

1. **One file a scene's run** (`confirm-<side>-i.n.xml`) given straight to the report. Each scene was then "failed"
   in every file that did not hold it, so the report read "branch failed 16 of 18, main passed 2 of 18". It confirmed
   two scenes that alone failed 1 of 3 on the branch.
2. **A confirm loop that let Gradle read its scene list from standard input** (`while read … done < flagged.txt`
   around `./gradlew`). Only the first scene ran. The other five were in no file. They read as failed on the branch
   and not passed on main, so cleared, though never run.

The gate's own `gate.sh` has neither fault: it reads the scenes into an array and combines each round. The report,
though, took whatever it was given.

## The change (`tools/corpus/report.py`)

- A flagged scene counts only the confirm files that hold it, so one file a round and one file a scene's run read
  the same.
- A scene with fewer than three confirm runs a side (`CONFIRM_RUNS`) is **not confirmed, and blocks**:
  "Not confirmed, too few confirm runs (blocks): … (0 run(s) on the branch, 0 on main; 3 each wanted)". A missing
  run never reads as a branch failure or a main pass.
- The rule is unchanged: a scene blocks when the branch fails it 2 or more of 3 and main passes it 2 or more of 3.
- The module's docstring says both layouts are read.
