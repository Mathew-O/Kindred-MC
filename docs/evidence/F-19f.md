## The cause

The route, not the prompt.

**The compatible route cannot cache.** Anthropic's page on its OpenAI SDK compatibility layer
(platform.claude.com/docs/en/api/openai-sdk, read 2026-11-15) says:
- "Prompt caching is not supported, but it is supported in the Anthropic SDKs";
- `usage.prompt_tokens_details` is "Always empty";
- use the native Claude API for "the full Claude API feature set (… prompt caching)";
- the layer "is primarily intended to test and compare model capabilities, and is not considered a long-term or
  production-ready solution for most use cases".

So on that route no request caches. `OpenAiCompatibleStrategist` reads `prompt_tokens_details.cached_tokens`, finds
nothing, and reports 0. The `cache read 0` in the run is that empty field, not a miss. The `cache write n/a` is right:
the route reports no write.

**The run went that way because a base URL was set.** `StrategistProvider.choose` takes the compatible provider whenever
`KINDRED_STRATEGIST_BASE_URL` is set. The native provider (`Provider.ANTHROPIC`, `ClaudeStrategist` on the Anthropic
Java SDK) is the only route that can cache. The manifest says that SDK is "development classpath only, not bundled in
the release jar", so a release jar has no native route to take.

**The native route's prompt is already in cache order.** In `ClaudeStrategist.call`:
- the system block is `StrategistPrompt.SYSTEM`, the same text every call, marked `cache_control`;
- the output schema (`Reply.class`) and the thinking setting are the same every call;
- the report, which grows each call (6,698 to 7,051 tokens here), is the one user message, after them.

Nothing that changes per call (a time, a position, a counter) comes before the stable part. The stable prefix is
about 2.5k to 2.8k tokens (E-20d), above the 512-token minimum of the build's default model. It was not measured on a
keyed run, because no keyed run has taken the native route.

## What it would take (for the owner and the lead)

Either of these gives the stance consultations a cache. Neither is done here.

1. **Bundle the Anthropic Java SDK in the release jar.** The version is already pinned, 2.75.0. This makes it a release
   dependency: the manifest's D3 and `anthropicJavaSdk` lines change, and so does the jar's size. Then a run keyed
   for Claude sets no base URL and takes `Provider.ANTHROPIC`.
2. **Keep the release jar as it is, and run the month's keyed runs on a development build** with the SDK on its
   classpath. Nothing ships.

Then one keyed run on the native route: two or more consecutive calls by one player within 5 minutes should show
`cache write` on the first and `cache read` near the prefix's size on the next. That is F-19f's acceptance.

Not proposed: caching on the compatible route (the page says it is not supported), or reordering the prompt (already
in order).

What this shows:
- **A write, then reads.** The first call wrote 6,183 tokens. Each of the 14 after it read the same 6,183 and wrote
  none, over about 8 minutes. The gaps between calls were 10 to 60 seconds, well inside the 5-minute life, so the
  prefix never changed between calls.
- **Only the report grew.** The input not read from the cache rose from 351 tokens to about 1,104.
- **The cached prefix is 6,183 tokens, not the 2.5k to 2.8k estimated above.** That estimate came from E-20d's
  `StrategistPrompt.SYSTEM`. The system text is now the instructions and the bundled Minecraft guide
  (`SYSTEM = INSTRUCTIONS + GUIDE`, F-19e), all of it the same every call.
- **Time:** the first call took 3,785 ms, the cached ones 1,160 to 1,985 ms.

So F-19f's acceptance holds on the native route. On the compatible route nothing can cache. Which route the release
jar has stays the owner's decision. Until then the lead's default holds: keyed runs that need the cache use a
development build, and the release stays as it is.

## Two small things found on the way (done in F-19f1, #372)

- On the compatible route the call line's `cache read 0` reads as a measured zero. It is not reported at all. Showing
  `n/a` there means carrying "not reported" through the budget arithmetic, which today adds the cached figure.
- Whether a release jar with `KINDRED_STRATEGIST_PROVIDER=anthropic` and no base URL fails cleanly, without the SDK on
  its classpath, was not checked.
