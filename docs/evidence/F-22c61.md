Status: in progress until the class runs and CI are in.

## Scope and implementation

Asked for by the lead. A narrowed gametest `fabric.mod.json`, left over from a local run of a few classes, nearly
reached a PR: 2 entrypoints instead of 177. CI would have run a fraction of the native suite and gone green.

Changed files:
- `tools/support-batch-01/support.py entrypoints`: a static check.
  - It lists every class under `companion-server-adapter/src/gametest/java` with a `@GameTest` method.
  - It fails when one of them is not registered in the gametest `fabric.mod.json`, when a registered class has no
    GameTest source, or when a class is registered twice.
  - Classes run apart from the suite are named in `RUN_APART`, each with its reason. The check also fails if one of
    those is registered.
  - It runs nothing. Test: `test_28c`.
- `.github/workflows/build.yml`: the support job runs it after the tracker check.
- The gametest `fabric.mod.json`: `NativeAttentionGameTests` is registered, at the end of the list, so no other class's
  place or batch changes. The check found it.
  - It has been in the tree since 25 October (7a2738c) and was never registered, so CI never ran its four tests.
  - [F-12a](F-12a.md)'s evidence names it as passing, which can only have been a local run.
- Run apart, as their own javadoc says ("not registered there"): `NativeDuelBenchmarkGameTests` and
  `NativeMeleeMechanicsGameTests`, both E-41b's, run alone with `-Dkindred.duels` and `-Dkindred.trials`.
  - Until now, running one meant editing the entrypoint list by hand, the same narrowing this check guards against.
  - `tools/run-apart.sh <Class> [-Dkindred.x=y ...]` is now the documented way. It refuses a class the suite runs. It
    puts that one class in the list for the run and passes the settings on. It always puts the list back, whether the
    run passes, fails or is stopped:
    ```
    tools/run-apart.sh NativeDuelBenchmarkGameTests -Dkindred.duels=200
    tools/run-apart.sh NativeMeleeMechanicsGameTests -Dkindred.trials=20
    ```

Test side only; no product change.
