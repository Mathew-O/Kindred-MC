# F-22c10 — A break walked over to is counted as each walk ends, not as it is asked for

Date: 2026-11-05
Agent / branch: Claude / claude/ci-green-1105 (CI fully green, F-22)
Build: on top of `cdec035` (main with M-00); recorded in [validation](../validation.md)
Status: complete (native)

## Scope and implementation

Root cause, in the product: `BuildRunner` commits to a break it walks over to, for up to eight walks, but counted them as
the runtime asked it for the next step. The runtime asks again and again while a walk is under way.
- **What followed:** the commitment ran out before the walk arrived. Planned again from there, the block under its feet
  came first, to be broken from the spot it had just left. The next plan did the same, and it walked between the two
  to the end of the hideout's ticks.
- **Where it was seen:** a full local suite on 5 November: between (…505, -53, …399) and (…505, -53, …400), each to
  break the block under the other.
- **Already fixed for placement:** the walk to a spot to place from was counted when it ends (the farm ward's first
  course). Breaks were not.

Changed file: `companion-server-adapter` `BuildRunner`: `breakWalks` counted in `finished`, as each "To break" walk ends.

A walk to a break that finds no way there now lets the break go, to be planned again from where it is. Kept, as a first
version of this change did, the same walk was asked for again, and eight failures in a row stopped the hideout and the
farm ward at their first steps (`full-m-1`: "No walkable route toward …").

A to and fro between two breaks remained, each to be broken from on top of the other: 1,231 walks each way in one run
(`builds-1`), 1,885 walks in another, against about 530 when it passes. As a placement already does, planned again for
the break it set out for two walks ago, it now breaks the one it walked over for, from the spot it walked to for it
(`lastBreakTo`, `breakToBefore`).

The same to and fro in placement: on CI for PR #25 a farm ward walked between two spots 1,104 and 1,102 times, each to
place a block from the other, and ended 195 of 480 placed. Placement's own guard committed to the block planned again,
which it was then never "at" on arriving. Now, planned again for the block it set out for two walks ago, standing in
the spot it walked to for the one between, it places that one from there (`lastPlaceStep`).
