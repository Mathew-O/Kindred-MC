## Scope and implementation
Enables bounded autonomous candidate generation, personality-biased selection via `PlayerDecisionLoop` and `TaskDirector`, and dispatch into qualified native skills (`native_eat`, `native_equip`, `native_mine`, `native_wait`) on established native players under explicit server policy.

1. **Candidate evaluation**: `PlayerRuntime.evaluateNativeCandidates(Entry, NativePlayerBody)` inspects local state without external cheats:
   - Evaluates hunger against hotbar food slots (0..8) producing `native_eat` candidates with urgency scaled to missing food level (urgency 20.0..100.0).
   - Evaluates inventory armor/shields matching unoccupied equipment slots via `body.equipmentDestination(slot)` producing `native_equip` candidates (urgency 55.0).
   - Evaluates reachable assigned resource-work patches in the player's loaded world producing `native_mine` candidates for target logs with owned hotbar axes (urgency 50.0).
   - Evaluates resting needs when injured but well-fed producing `native_wait` candidates (urgency 25.0).
   - Candidate UUIDs are deterministically derived from companion ID and task details so `TaskDirector` switching margin (3.0 points) enforces stable hysteresis across ticks.

2. **Policy and admission gating**:
   - Autonomy is admitted only when: established state, usable body, idle activity session, unlatched stop, no pending action/activity/setup flushes, and server edit policy is explicitly enabled (`edits.autonomousEditsEnabled() && edits.protectionCompatibilityKnown()`).
   - Default server policy (`ServerPolicy.deferredD4()`) strictly rejects autonomous admission, yielding `Action.WAIT` from `PlayerDecisionLoop`.

3. **Fenced dispatch and execution**:
   - `PlayerRuntime.beforeNativeTick` evaluates candidates and invokes `PlayerDecisionLoop.tick(...)`.
   - On `Action.PROPOSE_TASK`, dispatches via `dispatchNativeTask(...)` under a `PaidActivitySession` permit through `ActionArbiter` and `SkillRunner`.
   - Reused lease/task ID binds the running execution to the candidate ID, ensuring continuation bonus during task execution.
   - Clears `currentTaskId` on `Action.HALT`, terminal runner observations, halt commands, and dispatch failures.
   - Stop commands (`/player native lifecycle stop`) synchronously clear item use and inputs, latch stop, halt the activity session, and cancel active candidate execution.
