## Scope and implementation

User-visible behavior: none directly. Duel, speedrun, manhunt and build-battle results survive a restart (a match the
restart cut short is ended "Stopped: the server restarted", so no leave to strike survives it); every player death, a
person's or an AI player's, is recorded with its place, cause and killer.

Changed modules/files:
- companion-core `record/`: `WorldEvent`, `EventData`, `Ledger` (fold, replay, agreement check), `MatchLedger`,
  `ClaimLedger`, `DeathLedger`, `ActionLedgerView`, `Ledgers`; `match/MatchRegistry` (`Stored`, `drainChanges`,
  `stored`, `restore`).
- companion-persistence: `V12__world_record.sql`; `SqliteCompanionStore` (`record`, `worldEvents`, `allWorldEvents`,
  `checkActionLedger`; `appendEvent`, `prepareAction`, `transitionAction` and startup recovery each also write their
  event in the same transaction; append-only triggers).
- companion-server-adapter: `PlayerRuntime` (ledgers replayed at startup off the server thread, matches restored and
  flushed every tick and at stop, `record`, `playerDied`/`recordDeath`, `checkLedgers` once a game day), `NativePlayerBody`
  (`deathSource`), `KindredMod` (death hook calls `playerDied`).

Schema/configuration changes and migration coverage: schema 12 (the design said 10; main was already at 11). Existing
journal rows and action-ledger rows are backfilled as `journal` and `action` events in order (detail cut to 4,000
characters). `world_events` refuses UPDATE and DELETE by trigger. Covered by
`WorldRecordStoreTest.aSchemaElevenDatabaseGainsTheRecordWithItsJournalAndActionsInIt` (schema 11 → 12, backfill,
agreement, a schema 13 file refused) and by `SqliteCompanionStoreTest`'s downgrade helper now removing schema 12 too
(the schema 8 and schema 1 upgrades pass through 12).
