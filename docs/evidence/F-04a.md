## Scope and implementation
Explicit `/aiplayer native wait <1..4> <UUID>` and `native eat <0..8> <UUID>` use PlayerRuntime's existing Entry, SkillRunner, ActionArbiter, AdmissionBoard and ordered SQLite writer. Each request loads its persisted accounting period/limit and reserves one slice of at most five seconds. Durable matching acknowledgement precedes lease acquisition; no renewal or automatic task queue exists. New native players use their identity as admission principal, separately from controllers.

Eating checks the real owned slot, hunger and exact item/components/count, rejects chorus fruit, uses ordinary timed consumption, and verifies one native consumption plus the physical count change. Comparison copies are never inserted into inventories. The consumption override rechecks current authority and paid deadline immediately before native effects. Interrupted/changed/ambiguous outcomes block without retry. Native saves remain the only physical inventory persistence.

Stop immediately cancels inputs and fences admission callbacks. Terminal work releases admission and settles observed time. Unknown accounting outcomes stop for reconciliation. Disconnect/shutdown joins immutable accounting IO before closing the same writer; shutdown requires no subsequent game-thread callback. Requests are not resumed on reopen. Status reports loaded charged versus observed totals, and does not pretend unloaded totals are zero.

Dependencies: F-25b3, F-11b, FND-02. Schema remains 7; no dependency/config migration.
