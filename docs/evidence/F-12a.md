## Scope and implementation

Attention-state policy, fair multi-player round-robin scheduling, and budgeted native candidate planning ensure that multiple autonomous Kindred players share tick resources fairly while responding immediately to survival hazards without spiking tick time:

1. **Pure Core State Machine (`dev.kindred.core.attention`):**
   - **`AttentionState`**: Bounded four-state enum: `ROUTINE`, `ALERT`, `COMBAT`, `RECOVERY`.
   - **`ThreatKnowledge`**: Tri-state threat awareness: `CLEAR`, `PRESENT`, `UNKNOWN`.
   - **`WorkKind`**: Execution classification: `SURVIVAL_IMMEDIATE` vs `ROUTINE_PLANNING`.
   - **`SignalFrame` & `AttentionSnapshot`**: Immutable inputs and outputs fencing attention transitions, tracking tick sequence numbers and body generation.
   - **`AttentionStateMachine`**:
     - Transitions dynamically based on environmental danger, combat damage, and recovery status.
     - Implements quiet hysteresis: requires 60 quiet ticks (`QUIET_TICKS_FOR_RECOVERY = 60`) before transitioning into `RECOVERY`, and 100 quiet ticks (`QUIET_TICKS_FOR_ROUTINE = 100`) with safe health/hunger before returning to `ROUTINE`.
     - Fences stale attacks and deduplicates incoming damage signals across tick sequence numbers and body generations.
   - **`AttentionSchedulePolicy`**: Defines state-dependent cadences for routine planning:
     - `ROUTINE`: 20 ticks (1 Hz).
     - `ALERT`: 10 ticks (2 Hz).
     - `COMBAT`: 5 ticks (4 Hz).
     - `RECOVERY`: 40 ticks (0.5 Hz).

2. **Fair Multi-Player Round-Robin Scheduler (`AttentionWorkScheduler`):**
   - Manages multiple player instances fairly across server ticks.
   - Distributes planning opportunities using a round-robin pointer.
   - Single-use `WorkToken` pattern guarantees that granted tokens cannot be reused or carried over across ticks.
   - Storm coalescing: dirty flags coalesce rapid successive game events into bounded evaluation requests without queue explosions.
   - Soft time budget (2.0 ms per tick) bounding CPU consumption per tick during candidate generation.
   - Diagnostic counters (`SchedulerDiagnostics`) track tokens granted, tokens consumed, dirty events, and scheduling cycles.

3. **Runtime Integration (`PlayerRuntime`):**
   - **Essential vs Scheduled Path Split:**
     - The essential survival path (operator stop checks, authority verification, prepaid activity settlement, active skill runner ticks, immediate hazard retreat, and emergency eating) executes unconditionally on every server tick for every player.
     - The expensive routine planning path (workstation search, 3D approach traversal, recipe progression, tool crafting, and resource patch scanning) is scheduled via `AttentionWorkScheduler` according to each player's attention state cadence.
   - **Cached Routine Candidates & Cache Invalidation:**
     - Routine candidate lists are cached between scheduling cycles.
     - Conservative cache invalidation is triggered whenever the player's 36-slot inventory fingerprint (slot indices, item IDs, stack counts) changes, when setup configuration changes, or when the player's body generation increments.
   - **Shared Native Block Scan Budget:**
     - Enforces `MAX_BLOCK_CHECKS_PER_TICK = 128` across all players and candidate generators in a single server tick.
     - Bounded scanning applies to workstation discovery (`findNearbyWorkstation`), resource patch scanning (`budgetedResourceScan`), nearby mining block checks, and 3D approach traversal.
     - Out-of-bounds or unloaded chunk coordinates are filtered before checking the budget or incrementing scan counters.
