# F-22c53 — A resumed gather whose last drop is picked up as it walks completes

## Scope and implementation

User-visible behaviour: a player that resumes a paused gather, breaks its last log and walks to the drop now completes the
gather when the drop is picked up mid-step. Before, it stayed on "Resumed native_gather …" with its paid activity active
until something stopped it.

Found: `NativeGatherGameTests.partialGatheringThenPauseAndResumeDoesNotGatherOriginalCountAgain`, red on unrelated PRs today
(#125, #113, then #144's run 42805028977). F-22c48's diagnostics named the state:
- "acknowledged +1, completed not yet; logs 4; log blocks left false/false; remaining=0";
- the activity ACTIVE, and the last record a `native_gather` for the last log, still DISPATCHED.

A local copy with the runtime's status line in its message showed `runner=COMPLETING`.
- `NativeGatherAction`'s "completion check on resume only" ran on every tick while the run had a checkpoint, that is,
  every tick of a resumed run, not only its first.
- The resumed gather broke its last log and walked to the drop (`body.move`). The drop came into its inventory mid-step.
- On the next tick that check returned complete. It came ahead of the drop branch, which stops the walking and verifies
  the break.
- The body was still walking, so `isSettled` stayed false. `ActionArbiter.complete` therefore never settled, and the runner
  stayed COMPLETING: the activity ACTIVE and the record DISPATCHED.

Changed files:
- `companion-server-adapter` `NativeGatherAction`: the resume's completion check is made only on the resume's own first
  tick (`fresh`), before any work of the run, and it stops the body's inputs before it returns complete. Every later tick
  goes through the phases, so the last drop's branch stops the walking and verifies the break, and the gather completes
  from there.

Nothing is granted; the logs are the player's own pickups.

The fixture's staging, a copy of the pause-and-resume fixture:
- Two logs in the patch; it carries 2 and is asked for 2. It is paused once it holds 3, as before.
- Before "continue", the player is stood 2 blocks from the log left, level with it and in reach, so it breaks it from there.
- Each tick after the log is broken, its drop is held 1.1 blocks ahead of the player. That is in a player's pickup reach,
  but past the 0.9 at which the gather stops walking to a drop. So the drop is picked up as it walks, the tick its pickup
  delay ends.
- The pause-and-resume fixture's failure message now also names the runtime's status line (the runner's state among it).

Before this staging, a copy paused on the tick its last log's record read DISPATCHED reproduced CI's form in 1 of 7 runs,
and the unchanged fixture in 1 of 8. Neither is committed.
