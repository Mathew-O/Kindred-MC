# F-05e — Placement destination/claim fencing, distinct gather action IDs, and native collision pickup evidence
Date: 2026-10-17 EDT; report 2026-10-17.
Antigravity / uncommitted main, no commits. Complete for this child slice; parent F-05, F-07, F-08, F-13, F-25b, and F-25c remain open.

Stage A (shared-action correctness) establishes rigorous mutation gating, destination and claim fencing for block placement, multi-break distinct action tracking for log gathering, and authentic native player collision pickup without remote item insertion:

1. **`NativePlaceAction` Placement Gates, Support Fencing and Component Conservation:**
   - **Preconditions and Mutation Gates:** `permits(Intent.PLACE, target)` validates admission phase (`ISSUED`), valid claim ownership (`claims.holdsAll`), setup revision matching (`setup.revision() == setupRevision`), support block stability and replaceability at the placement position, and server policy.
   - **Support Drift Fencing:** Detects if the support block (or destination space) changed between plan/admission time and physical execution; denies placement if support was broken, replaced, or obstructed.
   - **Claim Revocation Gate:** If a claim expires or is contested prior to physical block placement, the placement call is refused without mutating the world or consuming inventory stacks.
   - **Exact Component-Aware Inventory Conservation:** Item conservation (`verifyExactPlacementConservation`) tracks the exact placed item stack, verifying that exactly one count was consumed from the designated slot and all 35 other slots (including custom components, damage, names, enchantments) remain perfectly intact.

2. **`NativeGatherAction` Distinct Action IDs, Multi-Break Tracking and Native Collision Pickup:**
   - **Monotonic Substeps and Distinct Action IDs:** For multi-block gathering tasks (e.g. gathering 2 logs under one lease), each block break generates a distinct action ID (`UUID.randomUUID()`) and sequential `substep=N` index recorded in `ActionRecord.preconditions()`, bound to the same parent `taskId` under the active lease.
   - **Causal Drop Observation:** Distinguishes pre-existing drops from drops spawned by the break by tracking item entities in the search volume before and after the block break receipt.
   - **Ordinary Native Collision Pickup (No Forced Insertion):** The player physically traverses into collision range (`body.move` with `Intent.MOVE` permitted under `native_gather`), allowing vanilla player collision physics in `player.playerTick()` to pick up the drop. No remote inventory insertions are performed.
   - **Pickup Delay and Ownership Fencing:** Preserves vanilla `ItemEntity.cannotPickup()` and pickup delays. If a drop cannot be picked up before the bounded timeout (80 ticks), the action completes without attribution and blocks further gathering rather than forcing collection.
   - **Breaker Attribution vs Third-Party Interception:** If drops from the break are collected by another player/entity or discarded, `NativeGatherAction` attributes `drops=uncollected; recipient=other` in the verified receipt and blocks further gathering without falsely reporting success.
