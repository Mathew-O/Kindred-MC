# F-22c50 — Main's CI runs are no longer cancelled by the next push

Date: 2026-11-10 (merged up to main on 2026-11-11)
Agent / branch: Claude / claude/ci-green-1110-maincancel
Build: workflow change only
Status: in progress until main's first run after the merge finishes.

## Scope and implementation

`build.yml`'s concurrency was `group: build-${{ github.ref }}` with `cancel-in-progress: true`. Each merge to main
cancelled main's previous run, which takes about an hour. With merges every hour or so, main had no finished run
after 6957e28. So "CI green on main" could not be shown, and an intermittent's A/B had no main result to compare
against.

Changed file: `.github/workflows/build.yml`. `cancel-in-progress: ${{ github.ref != 'refs/heads/main' }}`.
- A newer push to a pull request still stops its stale run.
- On main, a run is never stopped. A newer push waits, and of those waiting, GitHub keeps only the newest.

No product or test change.
