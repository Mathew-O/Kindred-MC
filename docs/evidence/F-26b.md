## Scope and implementation

The runtime refuses the dragon goal while the server's dragon fight is off ("The dragon fight is off on this server; an
operator must turn it on first"). The evaluation's bootstrap never turned it on, so a run with `goal=dragon` started its
three players with no goal at all and measured nothing. That is how the first probe past the portal (`e40c1-e0368f9`,
four seeds, run in a second container on 2026-11-06) went: every seed logged the refusal, and no goal step followed.

Now:
- with the dragon goal, the bootstrap turns the dragon fight on first, as an operator setting that goal would
  (`/aiplayer dragonfight on`); for any other goal it stays off, as a fresh server has it;
- a goal the runtime refuses is logged and put in the run's note (`eval-result.json`), so a run with no goal set says
  so.

Changed modules/files: `companion-server-adapter`: `EvalBootstrap`.
