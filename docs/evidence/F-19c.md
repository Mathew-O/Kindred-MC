## Scope and implementation

User-visible behavior: with the F-19b strategist switched on, Haiku's notes become the player's lessons for a world. A note may carry a habit that the local planner keeps to in every later life there, and each reply may set a focus on what to do next for five minutes. The local plan still plays every moment, and the survival checks always come first.

Changed modules/files:
- `companion-core/.../survival/PlanPreferences.java` (new): the vocabulary the planner and the goal read.
  - Habits: `MORE_FOOD` (three more food carried), `SPARE_PICKAXE` (a second spare pickaxe for the work below), `NO_CAVES` (dig its own way for ore), `SHELTER_EARLY` (dig in at dusk, from game time 11,500).
  - Focus: `FOOD` (hunt, and look for animals by day, until three more than the usual stock are carried) or `WOOD` (logs until sixteen planks' worth more than the wood kept, only where a tree stands).
  - At most four habits.
- `PortalRunPlanner`:
  - `plan(snapshot, facts, preferences)`; the old `plan(snapshot, facts)` is the same with none.
  - A focus puts its steps first while they still have work to do: `HUNT`, then the new `SEEK_FOOD`, or `GATHER_LOGS`.
  - `MORE_FOOD` raises the food stock; `SPARE_PICKAXE` packs three pickaxes for the work below instead of two.
- `StrategyAdvice`: adds `focus`, `habit` and `retire`.
  - An unknown name counts as none.
  - A habit without a note saying why counts as none.
  - `withStance` keeps the rest when surface-and-recover turns into play-safe.
- `ClaudeStrategist`: the structured reply has the three new enum fields. The prompt explains them: a focus for a real problem now; a habit only for a problem the report shows more than once, never one already kept; retire one only when it gets in the way.
- `ModelContextStore`: a note keeps the habit it teaches by name (`"habit": "MORE_FOOD"`; absent in older files).
  - The world's habits are those its notes carry.
  - A habit already kept stays with its first note.
  - Past four, the oldest habit's note becomes a plain note.
  - Retiring a habit keeps its note as a plain note.
  - Plain notes are dropped before ones that carry a habit.
  - A lesson already in the notes is kept once, however it is worded: at least half of all the words of four letters or more in the two notes are shared. Its first wording moves up to the newest, so a lesson learned again outlasts one learned once. A habit learned with it joins that note, unless the note already teaches another.
- `StrategistBridge`: hands the world's habits to each goal the player starts, as soon as the memory file is read. After each reply it records the note with its habit and any retirement, and logs `habits in this world now [...]` when they change.
- `PortalRunCampaign`:
  - Holds the habits and the focus in force.
  - `SEEK_FOOD`: out to the surface by day, then walking out to look; never at night.
  - `NO_CAVES` skips cave exploration.
  - `SHELTER_EARLY` counts the last of the afternoon as night for shelter.
  - The report lists the focus and the kept habits, and marks each note with its habit.
- Also in this change, from a suite failure: the goal's finishing rule for a hurt player now counts a foe that a swing knocked back up to five blocks as still in reach. This is the reach the running fight already uses to decide whether to break off. Before, a hurt player could switch to backing off from a zombie its last hit had knocked out of the three-block reach.

Dependencies satisfied: F-19b.
Schema/configuration changes and migration coverage: an optional `habit` field on notes in the per-world memory files. Files without it read as notes without habits; an unknown name reads as none. No SQLite or NBT change.
Requirements covered: AI-02, since the model still returns only names from fixed sets and text, never actions, items or code. AI-03, since the new fields are strictly validated in core. The "earn all progress" rule: a focus or habit changes the order and amount of ordinary work only.

### Wood first must not starve the route (sky-island run 11)

Sky-island run 11 (real time, `349c270`) was advised wood first at the start. It cut the island's one tree, four logs. The focus step was the route's own log gathering, which explores when no log is in reach, and exploring always yields some task, so the focus came first on every pass. The player explored over the void for 12 minutes with four logs in hand and never made a table or a pickaxe.

Fixed: wood first is now its own step, `CUT_TREES`. It cuts a tree in sight and nothing more, and is planned only while a tree is known; the search for one stays the route's own step. Looking for animals under food first is not done over the void either, since an island's animals are the ones on it.

### The finisher fixture

`goalFinishesAWoundedZombieInReachRatherThanTurningItsBack` failed once in a full suite on an idle machine, and once before under load.
- Its log showed a fight, then "Back off from zombie" while the zombie was still alive, then the fight cancelled as badly hurt.
- This fits the knockback path described above, which the finishing-rule change closes.
- A stress run of the fixture alone, twelve times in separate batches, passed 12/12 both with and without the change. So the flake was not reproduced in isolation, and the change is not proven to cure it.
- The full suite passed 229/229 twice after it.
