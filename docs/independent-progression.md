# AI-player progression
[Product](../minecraft_player_spec.md) · [Architecture](player-architecture.md) · [Tracker](feature-spec.md)

Autonomy is normal. Follow/help/wait are tasks, not operating modes. Legacy mode/scope fields are compatibility data; do not build a Companion/Independent selector.

E-12 provides durable personal/team milestone dependencies: registry recipes, materials, tools, workstations, observed destinations and verified postconditions. Choose feasible work from needs and commitments; missing skills produce honest blockers.

E-13 covers earned home/food, E-14 exploration/routes, E-15 Nether/recovery, E-16 gear/upgrades, E-17 integrated progression, E-39 End/Dragon and E-40 three-player completion. These reference the single tracker.

Temporary team roles reflect ability/resources/interests, not professions. Share stock through authorized reservations/transfers. Human absence does not determine AI needs; server admission and stop govern action.

Dragon completion is a production objective. Qualified skills/readiness and server policy authorize encounters; personality/chat cannot. Preserve conservative legacy restrictions through migration. Lost gear creates recovery work without erasing achievement history. Qualify earned progress with actual traversal, contention, restart, death and API outage.
